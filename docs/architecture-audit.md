# Architecture audit (Phase 0 — performed on the uploaded repository before any edit)

Baseline preserved as Git commit `428a598 baseline: original Lovable app`.

## 1. Original architecture
TanStack Start (React 19, Vite 7) generated by Lovable, deployed through `@lovable.dev/vite-tanstack-config` (Nitro → Cloudflare). Tailwind 4 + shadcn/ui + Recharts + TanStack Query. **Data source: a Google Spreadsheet** accessed server-side through the Lovable connector gateway (`sheets.server.ts`) with five tabs: Leads, Clients, Activities, Tasks, Settings. Browser → `createServerFn` (`crm.functions.ts`) → Sheets API.

## 2. Route / module inventory
`/` dashboard · `/leads` (table+kanban) · `/clients` · `/activities` · `/tasks` · `/reports` · `/settings`; `app-shell`, `login-screen`, `record-dialog`, `ui-bits`; `crm-hooks` (react-query over server fns), `crm-schema` (columns/vocabularies), `auth.tsx`.

## 3. Reusable
shadcn UI kit, `AppShell` layout, `KpiCard/SectionCard/PageHeader/StatusPill`, `RecordDialog`, chart styling tokens, Tailwind theme, `server.ts` error wrapper, Lovable error reporting.

## 4. Security vulnerabilities (all confirmed in code)
| # | Finding | Severity |
|---|---|---|
| S1 | **Four user accounts with plaintext passwords hardcoded** in `auth.tsx` and shipped to every browser | Critical |
| S2 | Session = `localStorage` JSON; role read from it; **no server-side authentication at all** | Critical |
| S3 | Every server function (`fetchTable`, `createRecord`, `saveRecord`, `removeRecord`) is **unauthenticated** — anyone who can reach the endpoint can read/modify/delete any tab | Critical |
| S4 | Spreadsheet ID hardcoded in `sheets.server.ts` | High |
| S5 | `isAdmin` checks exist only in React; "Assigned To" scoping is a client-side filter | High |
| S6 | No audit trail; "Created By/Updated By" are client-supplied strings | Medium |
| S7 | Sheet formula injection possible via CSV/cell values | Medium |

## 5. Data-integrity problems
IDs generated client-side as max+1 (race → duplicates); updates/deletes addressed by **spreadsheet row number** (shift after any delete); no foreign keys (company names as joins); "Converted Client" conversion = two independent writes (non-atomic, duplicate-able); money and dates stored as free text; whole tabs downloaded to the browser for every metric (dashboard computed client-side); 30-second full refetch polling; errors turned into empty/zero results.

## 6. Functionality preserved
Leads table/kanban/filters/CSV export, activities log, tasks, clients, reports (employee, source, lost reasons, monthly growth), dashboard KPIs, settings vocabularies, notifications bell, visual design tokens.

## 7. Target architecture
See `docs/architecture.md`.

## 8. Migration risks
Free-text assignee names ≠ user accounts; duplicate/missing legacy IDs; unparseable dates/amounts; "Converted Client" leads without a matching client row; activities referencing leads by company name; lockfile drift (`package-lock.json` out of sync, `bun.lock` stale).

## 9. Missing infrastructure
Supabase project (not available in this environment), SMTP for invites/resets (Supabase default mailer is rate-limited), Netlify site, production data export.
