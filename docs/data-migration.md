# Google Sheets → Supabase migration
1. Export each tab (Leads, Clients, Activities, Tasks) to CSV into a private folder; keep the original sheet read-only as the recovery copy.
2. Create the people first (Team → Invite). Historical *Assigned To / Owner / Account Manager* values are matched to profiles by **email or exact full name**; unmatched leads import unassigned (original text preserved in `notes`), unmatched tasks/activities are reported as errors.
3. Dry run: `node scripts/migrate-sheets.mjs --dir ./exports` (needs `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`, or `--lookups file.json` offline). Review `migration-report.json` (per-entity counts, `unaccounted`, every exception).
4. Apply to **staging first**: add `--apply`. Idempotent (upsert on `legacy_id`); safe to re-run after fixing the sheet. Writes an `import_jobs` row.
Mapping — Status: New Lead→new, Contacted, Meeting Scheduled, Proposal Sent, Negotiation, Converted Client→won (linked to the Clients row with the same company, else left at Negotiation for review), Lost→lost (reason "Other"), On Hold→nurture. Activity "Proposal Discussion"→proposal, "Follow-up"→follow_up. Task "To Do/In Progress/Completed"→todo/in_progress/completed. Dates accept ISO, DD/MM/YYYY; bad values are dropped, reported and kept in notes. Client payment fields are kept in `clients.notes` (no historical invoices are invented). Settings tab: reviewed manually (vocabularies now live in tables).
Reconcile: compare `report.entities` with sheet row counts; spot-check 20 records per entity; verify lead→client links; then cut over (stop sheet writes, announce, delete sheet connector access).
**Status: tool built and tested on fixtures (dry-run + unit tests). Not run against real data or a real database — no data/project access here.**
